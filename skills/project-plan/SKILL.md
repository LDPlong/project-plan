# project-plan（一次性脚手架）

本 skill 只做一件事：给项目装好“跨对话状态”机制，然后退场。

当前版本 0.2.1，变更见仓库 CHANGELOG.md。

装完之后，后续所有触发——任务开始前读清单、完成后更新、记录决策与坑——都由仓库 `AGENTS.md` 里的规则负责，**不再依赖本 skill 被调用**。原因很直接：skill 靠 description 匹配，是否命中不确定；`AGENTS.md` 是每轮都加载的常驻指令。

## 何时调用

- 项目刚建立，或刚确认目标与范围。
- 仓库里还没有 `PLAN.md`，或 `AGENTS.md` 里没有 `<!-- project-plan:begin -->` 块。

**不调用**：已经装好的项目——哪怕清单需要更新，也直接按 `AGENTS.md` 的规则改 `PLAN.md`。

## 步骤

1. **查现状**：`PLAN.md` 是否存在、`AGENTS.md` 是否已有标记块。
   - 两者都在 → 报告“已初始化”并停止，不要重复注入。
   - `PLAN.md` 在、块不在 → 只补注入块。
2. **确认三件事**（能从对话提取就不问；缺的合并成一次提问）：
   - 一句话目标
   - 可验证的验收标准（怎么算做成）
   - 非目标（明确不做什么）
3. **写 `PLAN.md`**：以 `references/PLAN-template.md` 为底，放在项目根目录。
   - 只规划当前里程碑，不要一次写到 M5。
   - 任务拆到“一条 commit 能概括”，填 1 条「进行中」、2-4 条「待做」。
4. **注入 `AGENTS.md`**：把 `references/AGENTS-block.md` 整块写入仓库根目录的 `AGENTS.md`。
   - 已有 `<!-- project-plan:begin -->` … `<!-- project-plan:end -->` → 整块替换，保证幂等。
   - 没有标记块 → 追加到文件末尾；文件不存在就新建。
   - 不要改动 `AGENTS.md` 里其他内容。
5. **自查**：运行自带脚本 `scripts/check-plan.ps1 -Path <项目根目录>/PLAN.md`（脚本随 skill 安装，位于 skill 目录下）。必需章节为 目标 / 非目标 / 进行中 / 待做 / 决策 / 坑；脚本同时检查重复章节、目标占位符、进行中数量和非空行数。
6. **交付说明**三件事：装了哪些文件、以后怎么验证、后续不再调用本 skill。

## 注入块的内容边界

块里必须**自包含**，不能引用本 skill（未来对话不会加载它）。至少覆盖：

- 状态只存 `PLAN.md` + `git log`
- 任务开始前读哪几块
- 任务完成后怎么更新、与代码放同一个 commit
- 决策与坑的写法
- 「进行中」≤1、任务粒度 = 一条 commit、总行数 ≤50
- 清单与 git 冲突时以 git 为准

## 不要做

- 不要在后续任务里重新调用本 skill 来“更新清单”——那是 `AGENTS.md` 的职责。
- 不要把 `PLAN.md` 放全局目录；一份清单只属于一个项目根目录。
- 不要替项目写业务内容，只装机制。
