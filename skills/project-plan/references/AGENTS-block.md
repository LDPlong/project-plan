## 项目状态（PROJECT-PLAN）

状态只存两处：`PLAN.md`（目标、为什么、下一步、坑）和 `git log`（改了什么）。

- **任务开始前**：读 `PLAN.md` 的「目标 / 进行中 / 决策 / 坑」，确认本轮任务在清单里；不在就先补进去再动手。
- **一条 commit 粒度的任务完成后**：勾掉完成项，从「待做」取一条移入「进行中」，清单与代码放在同一个 commit。
- **技术选型或取舍**：写「决策」，带日期和理由（写为什么，不写结论本身）。
- **超过 10 分钟才解决的异常**：写「坑」，格式为 现象 → 原因 → 解法。
- **清单规则**：任务粒度 = 一条 commit；「进行中」最多 1 条；总行数 ≤50，超了归档旧里程碑；已完成任务折成一行进「归档」。
- **冲突处理**：清单与 `git log` 不一致时以 git 为准；不抄代码改动，不记格式化、改名这类小改动。
